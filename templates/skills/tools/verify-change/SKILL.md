# ⚖ 校驗關卡 · 變更校驗


## 核心原則

```
變更 = 程式碼改動 + 文件更新 + 理由記錄
無理由的變更是隱患，無記錄的變更是災難
每一次變更都是歷史，每一個決策都要留痕
```

## 自動分析

執行變更分析指令碼（跨平臺）：

```bash
# 在 skill 目錄下執行
node scripts/change_analyzer.js                    # 分析工作區變更（預設）
node scripts/change_analyzer.js --mode staged      # 分析暫存區變更
node scripts/change_analyzer.js --mode committed   # 分析已提交變更
node scripts/change_analyzer.js -v                 # 詳細模式
node scripts/change_analyzer.js --json             # JSON 輸出
```

## 檢測能力

### 自動檢測項

| 檢測項 | 說明 |
|--------|------|
| **檔案分類** | 自動識別程式碼/文件/測試/配置檔案 |
| **模組識別** | 識別受影響的模組 |
| **文件同步** | 檢測程式碼變更是否同步更新文件 |
| **測試覆蓋** | 檢測程式碼變更是否有對應測試 |
| **影響評估** | 評估變更規模和影響範圍 |

### 觸發警告的情況

- ⚠️ 程式碼變更 > 50 行但 DESIGN.md 未更新
- ⚠️ 程式碼變更 > 30 行但無測試更新
- ⚠️ 新增檔案但 README.md 未更新
- ⚠️ 配置檔案變更未記錄
- ℹ️ 刪除檔案需確認引用已清理

## 變更前置檢查

在修改任何模組前，必須：

1. **讀取 README.md** — 理解模組定位
2. **讀取 DESIGN.md** — 理解現有決策
3. **評估影響範圍** — 此變更影響哪些部分
4. **確認變更理由** — 為什麼要改

## 變更後置檢查

程式碼修改完成後，必須：

### README.md 更新檢查

- [ ] 模組職責是否變化 → 更新職責描述
- [ ] 依賴關係是否變化 → 更新依賴說明
- [ ] 使用方式是否變化 → 更新示例程式碼

### DESIGN.md 更新檢查

- [ ] 新增設計決策 → 記錄決策及理由
- [ ] 修改現有設計 → 記錄變更及原因
- [ ] 引入新限制 → 更新已知限制
- [ ] 新增變更記錄 → 更新變更歷史

## 變更記錄格式

在 DESIGN.md 的變更歷史中新增：

```markdown
## 變更歷史

### [日期] - [變更標題]

**變更內容**: 簡述改了什麼

**變更理由**: 為什麼要改

**影響範圍**: 影響哪些功能/模組

**決策依據**: 為何選擇此方案（如適用）
```

## 自動觸發時機

| 場景 | 觸發條件 |
|------|----------|
| 設計級變更 | 修改架構、介面、資料結構 |
| 重構完成 | 重構任務完成時 |
| 程式碼變更 > 30 行 | 較大規模程式碼修改 |
| 提交前 | 程式碼提交前檢查 |

## 校驗流程

```
1. 執行 change_analyzer.js 自動分析
2. 識別變更檔案和受影響模組
3. 檢查文件同步狀態
4. 評估變更影響
5. 輸出變更校驗報告
```

## 校驗報告格式

```
## 變更校驗報告

### 變更概覽
- 變更檔案數: N
- 程式碼變更行數: +X / -Y
- 受影響模組: [模組列表]

### 文件同步狀態
- README.md: ✓ 已同步 / ⚠️ 需更新
- DESIGN.md: ✓ 已同步 / ⚠️ 需更新

### 測試覆蓋
- 測試檔案變更: ✓ 有 / ⚠️ 無

### 結論
可提交 / 需補充文件後提交
```
