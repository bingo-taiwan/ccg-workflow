## 身份與訪問管理 (IAM)

### 認證方式
```yaml
密碼認證:
  - 強密碼策略
  - 密碼雜湊 (bcrypt/argon2)
  - 防暴力破解

多因素認證:
  - TOTP (Google Authenticator)
  - FIDO2/WebAuthn
  - 簡訊/郵件驗證碼

單點登入:
  - SAML 2.0
  - OAuth 2.0 / OIDC
  - Kerberos
```

### 授權模型
```yaml
RBAC (基於角色):
  使用者 → 角色 → 許可權
  示例:
    - admin: [read, write, delete]
    - editor: [read, write]
    - viewer: [read]

ABAC (基於屬性):
  策略 = f(主體屬性, 資源屬性, 環境屬性)
  示例:
    - 部門=財務 AND 級別>=3 → 訪問財務報表

PBAC (基於策略):
  使用策略語言定義複雜規則
  示例: OPA/Rego
```

### JWT 最佳實踐
```yaml
簽名演算法:
  - 使用 RS256 或 ES256
  - 避免 HS256 (共享金鑰)
  - 禁止 none 演算法

Token 管理:
  - 短期訪問令牌 (15分鐘)
  - 長期重新整理令牌 (7天)
  - 令牌輪換
  - 黑名單機制

Claims:
  - iss: 簽發者
  - sub: 主題
  - aud: 受眾
  - exp: 過期時間
  - iat: 簽發時間
  - jti: 唯一標識
```

## 威脅建模

### STRIDE 模型
```yaml
S - Spoofing (欺騙):
  威脅: 冒充使用者身份
  緩解: 強認證、MFA

T - Tampering (篡改):
  威脅: 修改資料
  緩解: 完整性校驗、簽名

R - Repudiation (抵賴):
  威脅: 否認操作
  緩解: 審計日誌、數字簽名

I - Information Disclosure (資訊洩露):
  威脅: 資料洩露
  緩解: 加密、訪問控制

D - Denial of Service (拒絕服務):
  威脅: 服務不可用
  緩解: 限流、冗餘

E - Elevation of Privilege (許可權提升):
  威脅: 獲取更高許可權
  緩解: 最小許可權、輸入驗證
```

### 威脅建模流程
```
1. 識別資產
   └─ 資料、服務、基礎設施

2. 繪製資料流圖
   └─ 信任邊界、資料流向

3. 識別威脅
   └─ 使用 STRIDE 分析

4. 評估風險
   └─ 可能性 × 影響

5. 制定緩解措施
   └─ 技術控制、流程控制

6. 驗證和迭代
   └─ 滲透測試、程式碼審計
```

```yaml
縱深防禦:

  - 預設拒絕
```


## 資料安全

### 資料分類
| 級別 | 型別 | 保護措施 | 示例 |
|------|------|----------|------|
| 公開 | Public | 無特殊要求 | 產品文件 |
| 內部 | Internal | 訪問控制 | 內部Wiki |
| 機密 | Confidential | 加密+審計 | 客戶資料 |
| 受限 | Restricted | 加密+審計+MFA | 金鑰、PII |

### 加密要求
```yaml
傳輸加密:
  - TLS 1.2+（禁用 1.0/1.1）
  - 推薦: TLS_AES_256_GCM_SHA384 / TLS_CHACHA20_POLY1305_SHA256
  - HSTS + 證書管理

儲存加密:
  - AES-256-GCM（對稱）+ 金鑰與資料分離（KMS/Vault）+ 定期輪換

密碼儲存:
  - bcrypt (rounds>=12) 或 argon2，禁止 MD5/SHA1
```

### 隱私保護
```yaml
資料脫敏: 姓名(張**) / 手機(138****1234) / 郵箱(z***@x.com)
資料最小化: 只收集必要資料 / 限制保留期限 / 定期清理 / 匿名化
生命週期: 建立(分類)→儲存(加密)→使用(審計)→共享(脫敏)→歸檔(壓縮)→銷燬(安全刪除)
```

### 資料安全檢查清單
```yaml
- [ ] 資料資產清單 + 敏感資料識別 + 資料流對映
- [ ] 傳輸加密 + 儲存加密 + 訪問控制 + 資料脫敏
- [ ] 訪問日誌 + 異常檢測 + DLP
```

## 合規審計

### 合規框架速查
| 框架 | 適用範圍 | 核心要求 | 處罰 |
|------|----------|----------|------|
| GDPR | 歐盟使用者資料 | 資料保護、使用者權利 | 營收4%或2000萬歐 |
| SOC 2 | SaaS/雲服務 | 安全、可用、機密、隱私 | 失去客戶信任 |
| HIPAA | 醫療健康資料 | PHI保護 | $50K-$1.5M/次 |
| PCI DSS | 支付卡資料 | 持卡人資料保護 | $5K-$100K/月 |

### GDPR 使用者權利 (DSAR)
| 權利 | API | SLA |
|------|-----|-----|
| 訪問權 | `GET /users/{id}/data-export` | 30天 |
| 刪除權 | `DELETE /users/{id}/data` | 30天 |
| 可攜帶權 | `GET /users/{id}/data-export?format=json` | 30天 |
| 限制處理 | `POST /users/{id}/restrict` | 72小時 |

### SOC 2 關鍵控制
```yaml
訪問控制: MFA強制 + RBAC + 最小許可權 + 季度審查 + 離職即撤權
變更管理: PR審查 + 分環境部署 + 審批流程 + 回滾方案
監控告警: 安全事件監控 + 異常登入檢測 + 資料訪問審計
事件響應: IR計劃文件化 + 定期演練 + 72小時通知 + 事後覆盤
```

### 審計日誌要求
```yaml
必須審計: 登入/MFA/密碼變更 | 許可權/角色變更 | 敏感資料訪問/匯出/刪除 | 配置/部署變更
儲存: 不可篡改(WORM) + 加密 + 異地備份
保留: 安全事件>=1年 / 訪問日誌>=90天 / 變更>=3年 / 合規審計>=7年
```
